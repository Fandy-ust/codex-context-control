# 调度与性能

0.15.0 重点降低后台无效工作，保持预算提交的即时性。

## 界面刷新

| 状态 | 间隔 |
| --- | --- |
| 菜单展开 | 1 秒 |
| 设置窗口可见，或有运行中的聊天 | 2 秒 |
| 隐藏、已连接但空闲 | 6 秒 |
| 隐藏且未连接／服务不可用 | 15 秒 |

打开菜单、设置窗口或激活应用时立即刷新，不等待旧定时器。刷新任务不重叠，唤醒请求合并；定时器有容差以便系统合并唤醒。服务失联时按受限频率尝试恢复。

与原来固定两秒相比，按策略计算，隐藏空闲时轮询次数减少约 67%，无连接时约 87%。这是调度次数，不是对整体 CPU 或电池寿命的百分比承诺。

## 持久化与统计

观测事件合并为最多每 150ms 一次写盘；预算、开关、默认值和继承等关键变更仍立即保存。退出时刷新待写观测。界面和预检读取内存中的最新状态，不等待落盘。

统计仍最多两个 worker、八个待处理聊天。相同聊天并发合并；空闲 worker 优先接回曾分析过的聊天，减少换位后重复解析。默认空闲 30 秒后释放 worker。

## 测量

使用安装包内的 Node 22.23.3，本地模拟服务与约 37MB 合成历史：

- 1,000 条观测更新只产生 **2 次**落盘。
- 24 并发、1,200 次关键预算写入，P95 **34.2ms**；这些提交没有延迟合并。
- 统计缓存读取 P95 **1.14ms**。
- 10,000 次预算往返、50 次开关、200 次重连和异常恢复通过。

测试进程包含两个统计 worker 和额外的全量比对器，采样峰值 RSS 为 449.4MiB，不是菜单栏应用的常驻内存。Node 版本、缓存与机器负载都会影响数值；不把它与旧 Node 25 的单次采样直接换算成加速百分比。

原始摘要在 build/performance-0.15.0-node22.json。可运行 `npm run test:stress -- --large` 复现逻辑和采样；不调用真实模型。

## 0.15.3：图表悬停路径

当前统计后台仍最多两个 worker，单个聊天一次统计由一个 worker 串行执行；UI 解码及时间线聚合另在后台任务完成，macOS 决定实际核心分配。增加统计 worker 不会直接加速 SwiftUI 主线程上的鼠标追踪。

本机这个聊天约 63 MB 历史、862 条响应的一次采样：冷统计约 1.48 秒，缓存读取约 9–25ms，强制重读约 209ms。悬停本身不请求统计服务。旧实现还把横轴标签区域排除在命中范围外，未处理离开事件，导致高亮停留。

修复后，比例尺只在布局时读取，鼠标事件最多按 60Hz 合并；十字线与区间详情分开通知，数字与模型标签预先整理，折叠的原始记录不逐次创建。悬停期间自动刷新暂停；已返回的新数据延后应用，移开后更新。

使用当前聊天的只读统计快照（872 条响应、109 个区间）验证真实输入处理路径：10,001 次轴上坐标事件合并为 2 次更新，最后位置约 18ms 内写入状态；500 次悬停过程中图表主体构建仍为 1。退出会取消待处理坐标，避免旧点重新出现。这是隔离原生窗口的状态处理测量，不等于屏幕实际帧率；系统负载仍会影响显示。

## 0.15.5：超过解析缓存预算的历史

统计结果与解析事件分开缓存。即使原始事件因 64 MiB 预算被淘汰，只要文件指纹和数据库路径未变，仍可复用结果；发生变化或手动刷新时重新解析。worker 使用结果标识避免重复复制数组，控制服务复用序列化结果。当前聊天约 68 MB 历史的未变化读取从 267–348 ms 降至 0.81–0.89 ms；不增加 worker 数或解析缓存预算。后台 MAX 进度条也会暂停动画。

完整数据、失败记录与适用限制见 [2026-10-17 压力测试](STRESS_TEST_2026-10-17.md)。
