# 调度与性能

0.15.0 重点降低后台无效工作，保持预算提交的即时性。

## 界面刷新

| 状态 | 间隔 |
| --- | --- |
| 菜单展开 | 1 秒 |
| 设置窗口可见，或有运行中的聊天 | 2 秒 |
| 隐藏、已连接但空闲 | 6 秒 |
| 隐藏且未连接／服务不可用 | 15 秒 |

打开菜单、设置窗口或激活应用时立即刷新，不等待旧定时器。刷新任务不重叠，唤醒请求合并；定时器有容差以便系统合并唤醒。服务失联时按受限频率尝试恢复。

与原来固定两秒相比，按策略计算，隐藏空闲时轮询次数减少约 67%，无连接时约 87%。这是调度次数，不是对整体 CPU 或电池寿命的百分比承诺。

## 持久化与统计

观测事件合并为最多每 150ms 一次写盘；预算、开关、默认值和继承等关键变更仍立即保存。退出时刷新待写观测。界面和预检读取内存中的最新状态，不等待落盘。

统计仍最多两个 worker、八个待处理聊天。相同聊天并发合并；空闲 worker 优先接回曾分析过的聊天，减少换位后重复解析。默认空闲 30 秒后释放 worker。

## 测量

使用安装包内的 Node 22.23.3，本地模拟服务与约 37MB 合成历史：

- 1,000 条观测更新只产生 **2 次**落盘。
- 24 并发、1,200 次关键预算写入，P95 **34.2ms**；这些提交没有延迟合并。
- 统计缓存读取 P95 **1.14ms**。
- 10,000 次预算往返、50 次开关、200 次重连和异常恢复通过。

测试进程包含两个统计 worker 和额外的全量比对器，采样峰值 RSS 为 449.4MiB，不是菜单栏应用的常驻内存。Node 版本、缓存与机器负载都会影响数值；不把它与旧 Node 25 的单次采样直接换算成加速百分比。

原始摘要在 build/performance-0.15.0-node22.json。可运行 `npm run test:stress -- --large` 复现逻辑和采样；不调用真实模型。
