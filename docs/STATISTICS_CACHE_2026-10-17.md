# 持续追加与多聊天缓存 · 0.15.6

本轮针对持续新增记录时的统计延迟。0.15.5 已解决文件不变时的重复读取，但新增一条消息后，超过 64 MiB 解析缓存预算的历史仍可能全量重读。

## 实现

新增 `src/statistics-events.mjs`，只对统计 worker 的内存缓存投影事件：保留消息/工具的可见文本、图片条目类型、计时、用量、模型设置、fork 边界、压缩替换历史及每条事件的序号；去除统计不用的密文、图片内容和工具完成事件中的重复输出。

完整原始读取接口保持原样，原始 JSONL 不修改。解析缓存仍最多 4 个文件、64 MiB 的保留数据预算，worker 仍最多 2 个、每个 384 MiB 旧生代限制。缓存预算计数改为投影后序列化数据的字节数，不将它描述为进程实际内存。

投影白名单与统计消费者必须同步维护；新增统计字段时先补等价性测试，再增加保留字段。未知事件保留位置，未知响应项目保留类型/ID，不会删除条目或改变 fork 的 ordinal 边界。

## 等价性与压力检查

- 对合成记录每个前缀比较投影与完整读取的全部统计输出，覆盖模型/档位、普通回复、工具、推理项目、用户追加、图片、压缩、费用与计时。
- 验证压缩替换历史和 rollback 拒绝行为一致。
- 大载荷/小缓存预算下保持有效事件；追加后只读新字节，结果与完整重算一致。
- fork 保留相同字节/条目边界，父聊天后续输入不进入分支。
- 32 个聊天反复切换 5 轮、160 次请求，结果不串线；最多 2 个 worker、12 项主进程结果缓存。空闲回收后重新加载与完整重算一致。
- 当前真实聊天只读比较：11556 条记录、972 次响应，投影与完整读取结果相同；约 69.3 MB 原始历史对应约 11.4 MB 保留数据。

## 隔离追加对比

从真实聊天及其继承记录创建本机临时副本，只往副本追加 30 轮合成消息；测试结束删除副本。前后实现读取同一份记录，交替测量顺序，每轮比较全部统计输出，排除 generatedAt 时间戳。

| 指标 | 完整事件缓存 | 统计字段缓存 |
| --- | ---: | ---: |
| 读取 + 统计中位数 | 178.33 ms | 4.47 ms |
| P95 | 233.05 ms | 9.64 ms |
| 30 轮累计读取 | 2080284855 字节 | 18450 字节 |
| 新增记录总量 | 18450 字节 | 18450 字节 |

30 轮结果全部一致。改进来自减少无用缓存载荷和重复解析，不是提高并发。这是一次本机只读/隔离测试，不代表整页显示延迟、所有聊天的收益或常驻内存下降比例；超大可见文本仍可能超过缓存预算，届时按既有规则淘汰。

## 复现

```sh
node --test test/statistics-projection.test.mjs test/statistics-performance.test.mjs
node scripts/benchmark-statistics-append.mjs <chat-id>
```

追加基准读取本机现有记录、建立临时副本，输出只有计数与耗时。不调用模型、不修改原始历史、不输出聊天正文。结果在 `build/iteration-append-benchmark.json` 与 `build/iteration-live-projection.json`，不随仓库或安装包分发。

## 回归与安装检查

完整回归 118 项中 117 通过、0 失败，最终安装包专项在构建后独立执行。真实聊天也通过实际 worker 的 384 MiB 旧生代限制，未提高并发或内存上限。

首次回归再次遇到辅助运行时版本检查的 5 秒超时，并非成功读取到不兼容版本。安装器现只对超时重试一次，两次都超时则明确提示稍后重试；成功读到不兼容版本立即拒绝。补充了重试次数和错误区分检查，最终完整回归通过。
