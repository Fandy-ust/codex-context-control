# 拓展上下文

「拓展上下文」与「提前压缩修复」是两个独立开关。前者调整本地窗口目录和保护阈值，后者选择可选的修复版运行时，互不代替。

## 开关与状态

- **关闭**：使用 Codex 各模型原生目录的上限和可用比例。面板、菜单栏及全局默认都受这个上限限制。
- **开启，等待 Codex 启动**：只保存了设置，尚未有运行连接，不能算已生效。
- **等待重开**：已运行的 Codex 仍使用旧的配置快照；请完整退出并重新打开。
- **已生效**：已连接的运行时使用拓展目录，可用上限为 920K，最晚 904K 压缩并预留至少 16K。

新安装默认关闭。升级已有 0.12／0.13 安装时，会保留此前已经启用的拓展；之后显式关闭会被保存，不因重装而开启。

## 关闭后怎样处理预算

超出原生上限的聊天预算会降低到该模型的原生上限，压缩阈值也会相应降低。已有的较小预算保留实际容量。全局默认同步限制；新聊天按所选模型再次检查，fork 继续继承父聊天。

切换等待重开期间，界面立即按目标模式显示范围，并暂停不匹配连接的预算编辑。当前运行时的读回值可能仍是旧值，会明确显示等待重开。重新开启只放宽可选范围，不自动把已降低的预算重新扩大。

原生目录例如标注 872,000、可用比例 95% 时，可用容量是 828,400；1K 精度的滑条上限显示为 828K。具体值来自当前本地模型目录，不写死为这个例子。

## 实现与适用范围

拓展使用独立模型目录，不修改签名的 Codex 应用，也不需要额外下载修复核心。目前验证的运行时版本为 Codex 0.160.0。开关存放在本地支持目录的 `context-extension.json`。

920K 是本工具采用的运行上限，不保证每个模型服务端都接受同样长度。长输入实测覆盖 Sol 系列；其他模型按用户选择启用。新输入检查与原生压缩使用本地估算及运行时记录，超大工具结果等仍可能产生额外开销。
