# 使用说明

[English](en/USAGE.md) | **简体中文** · [首页](../README.zh-CN.md)

## 正常启动与按需设置

- **Context Manager** 是控制面板。
- **原来的 Codex 图标** 继续用于日常启动，控制服务会随运行时按需接入。
- 从 **Mac 菜单栏或 Windows 系统托盘的额度图标**打开聊天概览。点击「打开主窗口」即可调整；关闭设置窗口后入口保留。

安装后第一次需要正常重开一次原来的客户端。之后直接打开/继续聊天即可，无需先打开面板。面板关闭时，预算控制继续工作。启动时从本地缓存显示聊天与最近用量，后台增量同步；未接入的聊天显示缓存状态。可以先保存预算，等待连接与新的用量记录后再应用。

自动接入只显示菜单栏入口，不弹出或抢占设置窗口。手动从 Mac 的 Spotlight/Finder 或 Windows 开始菜单打开 Context Manager，可进入主窗口。菜单中的「退出菜单栏入口」只关闭这个界面入口，已保存的预算控制继续运行；下次启动 Codex 时入口会再出现。

## Fork 预算继承

0.5.2 起，在已接入的桌面连接里使用普通 fork，会在创建分支时带入父对话已启用的独立预算。窗口、自动压缩阈值、下一轮预留和手动保留下限一并复制。分支从 revision 1 开始独立保存，修改任意一个对话不会修改其他对话的副本。

继承预算优先于 fork 请求中的全局默认窗口；其他配置、模型选择和权限参数仍保留。若指定的新模型目录上限容不下父预算，明确报错；不静默恢复成更大的默认窗口。无预算、已停用、临时 fork 或用 rollout path 指定来源的请求保持原生行为。已存在的分支不会被未来父设置追溯覆盖。新功能需正常重开 Codex 载入 0.5.2 桥接。

## 双滑块与高级设置

| 输入 | 含义 |
| --- | --- |
| 实际可用窗口 | 共用轨道上的白色滑块，按 1K 步进；显示值就是目标可用容量 |
| 自动压缩阈值 | 同一轨道上的蓝色滑块，按 1K 步进；同时显示占窗口的比例，支持 80/85/90% 预设 |
| 下一轮预留（高级） | 给新输入、输出与工具内容留下的额外空间 |
| 必须保留量（高级） | 可选手动下限，适用于你明确知道必须保留多少内容的场景 |

拖动窗口至 700K、选择 90%，压缩阈值即为 630K。以后只改窗口大小，阈值按所选比例联动并向下取整到 K。单独拖动蓝色滑块会更新所选比例。两点之间的灰色段是窗口上限减去压缩阈值的余量。两侧 − / ＋ 每次调整 1K；点击应用后才提交。200K/400K/800K 窗口预设按可用容量解释；“最大”为当前可用上限向下取整到 K，例如 828.4K 取 828K。

工具按模型实际比例自动反算底层整数配置。95% 模型上，700K 对应底层 `ceil(700000 / 0.95) = 736843`；运行时报告 `floor(736843 × 0.95) = 700000`。滑条的窗口最小值为 2K、压缩阈值最小值为 1K，上限由当前模型与原生压缩规则决定。显示和提交使用同一个整数 K 值；缩小窗口后仍需通过容量、预留和用量预检。

**为什么是 95%？** 当前已验证版本的模型配置用 `effective_context_window_percent` 指定可用输入比例，默认值为 95。源码注释说明，剩余空间用于为系统提示词、工具开销和模型输出预留余量。这是客户端的预算规则；仅凭该字段不能认定 API 服务端强制要求固定预留 5%。参考所验证源码的 `codex-rs/protocol/src/openai_models.rs` 中 `ModelInfo.effective_context_window_percent` 与默认值函数，以及 `codex-rs/core/src/session/context_window.rs` 中窗口乘以该比例的计算。

旧预算原样保留。例如旧底层窗口 700K、阈值 600K，滑条显示实际可用 665K、阈值 600K，比例显示约 90.2%。旧值若不是整数 K，编辑草稿向下取整到 K，顶部已保存预算仍显示原值。打开面板、拖动或预检都不会自动改写预算。

面板在顶部显示最近读回值与已保存预算。调整后、下一次正常请求完成前，旧值标为“上次读回窗口（待更新）”；只有新窗口读回并与当前预算一致后，才标为“已确认可用窗口”。窗口数值表示容量上限，最近请求用量单独显示。

## 状态

| 状态 | 含义 |
| --- | --- |
| 等待接入 | 客户端还没有通过桥接连接该聊天 |
| 等待用量记录 | 尚无足够新鲜的数据进行预检 |
| 等待轮次结束 | 请求继续生成，调整已排队 |
| 需要先压缩 | 近期用量加预留放不进新的预算 |
| 正在应用 | 目标聊天在重新加载，新的输入暂时排队 |
| 等待下一轮确认 | 配置已经提交，尚未读回真实窗口 |
| 窗口已确认 | 下一轮报告的窗口与计算的目标一致 |
| 需要处理 | 实际值不匹配或恢复过程出错，查看具体原因 |

窗口已确认只确认窗口读回；压缩阈值没有独立的读回字段。阈值设置行为通过本地模拟服务的集成测试验证，不会在真实聊天里额外触发模型请求来“证明”阈值。

## 需要先压缩时

可以使用原客户端的原生压缩方式，或面板的“原生压缩…”按钮。面板会在执行前明确确认。压缩通过你现有的 Codex 运行时执行，可能使用现有模型额度。

压缩完成后，等待正常下一轮交互产生新的用量记录，再重新预检。不会把压缩后保留量硬编码成 100K，也不会保证压缩到指定长度。

## Hook stats

在 `/hooks` 审核新增的 Context Control 命令。它只返回界面文字，不向模型注入额外上下文。原来的 Speed hook 会继续独立运行。

当前原生 Hook stats 接口不支持第三方输入框和滑块，因此编辑在独立面板中完成。单条 hook 的输出是该轮的历史快照；实时状态请看控制面板。

## CLI

在源码目录中：

```sh
node src/cli.mjs doctor
node src/cli.mjs list
node src/cli.mjs set-usable CHAT_ID 700K 90
# 省略比例时使用 90%
node src/cli.mjs set-usable CHAT_ID 400K
# 兼容旧脚本的底层配置入口：原始窗口、绝对阈值
node src/cli.mjs set CHAT_ID 400K 320K
```

CLI 保留 token 级精度与最多两位小数的百分比兼容性；1K 步进只适用于原生滑条界面。

`停止自动应用` 保留当前运行时窗口，只关闭后续自动应用。已开始的重新加载事务会完成。恢复默认窗口需要显式选择合适预算并重新应用。

## 常见情况

- **fork 名称重名或编号落后**：0.6.1 起，控制面板约每两秒读取原生名称，避免旧桥接快照把（2）显示成原名、把（3）显示成（2）。长标题保留末尾编号。已归档对话从列表隐藏；其预算仍保留，取消归档后可再次显示。

- **先出现中间窗口，再下一轮才是目标窗口**：0.5.1 修复了连续预算更新的排队与用量有效性问题。更新后需正常重开 Codex 载入桥接；`doctor` 的 `loadedBridgeVersions` 应显示 0.5.1。未通过容量预检或本轮正在运行时仍会等待，不会强制压缩。
- **接口成功但窗口不变**：查看是否仍在等待下一轮确认，以及是否有其他客户端/运行时持有同一个聊天。
- **面板没有接入**：首次安装后正常退出并重新打开原来的 Codex；查看 doctor 的 `automaticStartup` 和 bridge 数。若手动关闭了本工具的登录登记任务，重新安装以恢复。
- **重启后看起来没有反应**：先看屏幕顶部右侧菜单栏的 Context Manager 机器人图标。macOS 提供此开关时，可在「系统设置 → 菜单栏 → 允许在菜单栏显示」检查独立的 **Context Manager** 是否开启。0.4.0 的脚本应用入口可能无法独立列出，请升级到 0.4.1。doctor 的 `connectedBridges` 判断控制连接；`menuBar.created` 表示菜单对象已创建，`menuBar.ready` 进一步要求菜单窗口报告可见且位于屏幕范围内。这些是诊断信号，不能保证没有被系统隐藏或其他项目遮挡。
- **登录时同时自动打开 Codex**：系统不保证登录任务之间的执行顺序；如果 Codex 先于环境登记启动，需正常重开一次。普通 Dock/Spotlight 启动已通过独立应用测试，真实桌面的状态以 doctor 为准。
- **运行时更新后无法调整**：未验证版本保持透传；运行集成测试，通过后再更新版本允许列表。
- **模型上限未知**：等待正常使用使 Codex 刷新模型目录；不要用另一个模型的数值代替。
- **Hook 没有显示**：确认 `/hooks` 已审核该定义。预算控制不依赖 hook 运行。
