# 缓存写入为零：原始响应实验

2026-10-16，使用本机 Codex 0.160.0 测试。完整的脱敏数字见 [测试记录](cache-write-probe.json)。

## 已测到什么

使用现有 ChatGPT 登录，在临时目录创建 ephemeral 测试会话，连续发送三次固定合成内容，要求只答 OK、不调用工具。分别测试 GPT-6.1 Sol 和 GPT-6 Astra。捕获 `rawResponse/completed.usageMetadata.metadata` 中原始 usage 的字段存在性与数字，不保存提示词、输出正文、账户标识或凭据。

两模型的六个响应均明确包含 `input_tokens_details.cache_write_tokens: 0`，不是字段省略。Astra 的三次输入为 20,270、21,762、21,782，缓存读取为 8,960、20,096、21,632；Sol 的对应输入为 20,266、21,758、21,778，读取相同。缓存可复用前缀增长，但该通道的写入计量保持零。

另用同一个已安装运行时连接本机模拟 Responses 服务，依次发送：

| 上游字段 | 原始通知 | 规范化通知／持久日志 |
|---|---|---|
| 缺失 | 保持缺失 | 0 |
| 明确 0 | 保持 0 | 0 |
| 明确 60 | 保持 60 | 60 |

因此：客户端能够接收非零写入，普通日志确实会丢掉“字段缺失还是明确为零”的区别；但本次真实 ChatGPT 登录测试的零值已在上游响应中明确出现。不能扩大为所有 API、所有账户都返回零。未用 API key 发起付费对照请求。

## 官方计费规则

[Codex 价格说明](https://learn.chatgpt.com/docs/pricing) 明确区分：Codex credits 没有独立缓存写入收费，API-key 用量按公开 API 价格执行。这与本次 ChatGPT 登录路径的计量相符，但不表示服务端没有实际建立缓存，也不揭示其内部实现。

[公开 API 缓存说明](https://developers.openai.com/api/docs/guides/prompt-caching) 展示了非零 `cache_write_tokens` 及输入拆分公式。应把“计费用量”与“物理缓存新增量”区分开。

## 如何计算，而不是简单填零

设单次输入为 I、缓存读取为 C，尚未计量的 API 等价写入为 W：

```
0 ≤ W ≤ I − C
基线 B = (I − C) × 普通输入价 + C × 缓存价 + 输出 × 输出价
API 等价费用 = B + W × (写入价 − 普通输入价)
```

全部按百万 token 单价换算。GPT-6 的写入价比普通输入高 25%，所以额外写入的预算上限是“未命中输入 × 普通输入价 × 25%”，不是把整份写入价再加一遍。按每个请求自己的模型、档位和长短上下文费率求和。模型、档位或用量未知的请求仍单独排除；这不是所有未知因素都覆盖的实际账单上下界。

相邻读取量差值不是精确写入量：它包含后续输入、前一轮输出、缓存边界、压缩、失效与复用范围的影响。同样的 I、C 可以对应不同的写入策略；仅靠既有 token 记录不能唯一反演 W。App 主金额使用官方公式和上游返回计量，不自行补写入量。上面的范围是额外推导，仅在折叠的假设分析中展示，不是官方计费公式或实际账单上下限。

## 复现

```
node scripts/probe-cache-writes.mjs
node scripts/probe-cache-writes.mjs --live
node scripts/probe-cache-writes.mjs --live --astra
```

第一条只连接本机模拟服务，不联网调用模型。后两条明确请求使用现有 ChatGPT 登录，每次三条隔离请求，会消耗少量现有额度；不修改主聊天，不使用 API key。报告输出到忽略的 build/cache-write-probe 目录。真实测试与普通测试分开，CI 不自动调用真实服务。
