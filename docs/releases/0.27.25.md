# Context Manager 0.27.25

## Agent context control

- `chat show current --summary` resolves and validates `CODEX_THREAD_ID`, then reads only the selected chat. It separates requested and loaded budgets, numeric observation freshness, estimated headroom, model limits, available actions and recent operation receipts. Missing usage stays unknown.
- Preflight is read-only. `budgetValid`, `evidence`, `execution` and `registered:false` distinguish a viable proposal from an action that can run now. Local inherited usage is checked on demand without a model request; state changes invalidate that evidence.
- CLI budget changes and compaction requests return persisted operation receipts. Reuse `--request-id` for the same intended action; a different action cannot reuse the key. Budget revision conflicts provide structured recovery guidance. `chat operations ID`, `chat operation ID OPERATION_ID` and `chat cancel ID OPERATION_ID` provide scoped inspection and cancellation of waiting compaction.
- `chat compact current --when-idle --request-id CONFIRMED_ID` registers one compaction after the user's agreement. It binds the turn, model, budget revision and history branch, expires after 15 minutes, and cancels or becomes superseded after relevant changes, interruption or disconnect. At execution the bridge checks again and acquires its existing compaction lock. It neither interrupts the turn nor generates a continuation message. A service restart does not replay pending or uncertain actions.
- Operation history is bounded to 200 receipts. Cancellation applies before compaction starts; it does not undo completed compaction or unload an already applied budget. Unknown outcomes require inspection, not blind retries.
- `chat speed ID --summary` reports recent numeric speed samples, configuration groups and a comparable recent/baseline comparison. It reuses the existing bounded history workers without context tokenization or full statistics output. Insufficient baseline samples keep change estimates unknown.

## Interactive skill

The bundled skill defaults to quality-first and supports balanced and speed-first choices. It assesses task-specific context value and estimated growth, discusses tradeoffs through optional asynchronous interviews, continues safe work with comfortable headroom, and yields at a checkpoint when an unresolved decision could expose the next stage to compaction. The skill describes the installed CLI's execution boundaries and avoids repeated polling, model-catalog downloads and additional Codex monitoring servers.

The shared CLI, service and bridge implement the same behavior for macOS and Windows. macOS retains its native interface; no additional UI status panel is introduced. Installed older bridges require a normal Codex restart before deferred compaction is available. Windows native packaging and UI/installer validation are performed in CI, separately from local macOS validation.
