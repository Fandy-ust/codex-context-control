# Context Manager 0.27.23

Chats whose earlier history was stored as `.jsonl.zst` can now load statistics without manually restoring files. Plain and compressed representations share one logical identity; inheritance offsets are checked against decompressed bytes. The reader streams inside the existing bounded statistics worker, preserves numeric/source caches, and reports missing, conflicting or damaged records separately. Startup discovery does not decompress all cold chats.

A fork can load a proven expansion before its first message. The proof comes from the budget actually loaded by the current runtime and requires unchanged model/percentage plus nondecreasing window, compaction threshold and reservation headroom. Other changes can read valid numeric observations from the exact local history on demand. New input, an unfinished turn, compaction, rollback or a model change invalidates old usage. Shrink checks remain enforced.

Manual messages and queued tasks cannot silently run under an unapplied saved budget. Existing-thread resume responses no longer claim that newly supplied configuration was applied. Both desktop interfaces distinguish a loaded budget awaiting readback from a confirmed runtime window, and context failures no longer remain labelled as loading. macOS also clears old details when switching chats.

Normal startup compatibility checks export the runtime's compiled protocol schema locally and cache evidence by runtime identity and manager version. They do not initialize an additional app-server, access accounts or fetch model/plugin catalogs. Schema evidence is not presented as actual runtime configuration readback. The existing runtime remains responsible for that confirmation.

## Validation

- Bundled Node 22.23.3 on Apple Silicon macOS: 532 tests, 519 passed, 13 platform/condition skips, zero failures. Architecture/route checks and native macOS build passed.
- Local simulated Responses endpoint with the installed Codex runtime: first fork expansion completed with no model request; the first normal message reported 680,000 tokens. No external model request or account credential was needed for these tests.
- Read-only validation of the affected parent and fork succeeded across three/five source segments, including two compressed ancestors. One worker was reused; warm results read zero additional history bytes. One local sample measured full statistics at approximately 0.6–1.2 seconds cold and 1–2 milliseconds warm; these are observations, not performance guarantees.
- Historical compensation integration no longer assumes every newer native runtime reproduces the original premature-compaction defect. Enabled compensation, restoration and real usage thresholds remain checked.
- Windows shares the same reader, preflight, bridge and renderer changes. Native Windows build, UI and installer validation run in the repository's cross-platform CI; they cannot be executed on this Mac.

Update the manager normally, then reopen Codex once to load the new bridge. The manager's statistics service can use the history fix immediately after its update. User histories and saved budgets are preserved.
