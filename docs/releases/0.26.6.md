# 0.26.6 — Codex 更新兼容保护

Windows 与 macOS 共用版本，通过 GitHub Actions 双平台检查后发布。升级后请正常退出并重开 Codex，使新的启动兼容保护生效。

## 行为

- 只对明确识别的直接 stdio app-server 启用增强。`--print-startup-config`、`--startup-sign-out`、proxy、daemon、帮助、其他传输、未知子命令/选项及歧义参数保持原生透传。
- 在消费桌面协议之前，用隔离的临时 Codex 目录验证实际运行时：`initialize` → `initialized` → `config/read`。不发送模型请求，不读取用户聊天或登录文件，不改生产配置。
- 开启上下文拓展时，额外检查管理器注入的目录路径、窗口和压缩配置被运行时读回，避免新 CLI 静默忽略这些参数。
- 运行时真实路径、文件属性、macOS 内部 CLI、管理器版本/buildId 或注入配置变化，会使旧验证失效。成功记录最多复用 24 小时；失败记录冷却 60 秒，之后下次启动可重试。没有后台定时任务。
- 准备或验证失败时，本次使用原始运行时、原始参数及环境启动。已发送的请求不重放，已建立的连接不自动换进程。未初始化就异常退出的增强进程会使后续启动暂时回到原生模式。
- 成功验证后保留现有统计、逐聊天预算、上下文拓展、新聊天默认预算、分支继承和任务队列逻辑。原生模式暂不可用的增强设置仍保存，之后验证成功会重新启用。
- Windows 启用接入前的 exe 链路探针使用完整握手，并要求增强验证通过。共享运行时检查同时用于 macOS。
- 断连日志区分 EOF 超时、输入/输出错误、输出关闭、父进程消失。原生进程退出后继续排空输出，再关闭桥接读取器。

## 诊断与边界

`context-manager doctor` 的 `runtimeCompatibility` 返回最近一次验证记录，包括运行时版本、平台、管理器版本、原因和时间。它是历史证据，不能代替当前聊天的唯一有效连接和窗口读回。

记录位于管理器数据目录的 `runtime-compatibility.json`。这里只存身份摘要与状态，不保存参数值、模型目录内容或协议正文。验证缓存写入失败不阻止原生启动。

未命中缓存的验证有启动开销：版本探测限时 1.5 秒，握手限时 4 秒，退出清理有界。运行时补丁选择仍使用已有逻辑。启动配置读取等短命命令不经过这套探针，也不加载增强模块。

此版本验证启动协议及管理器启动配置，不能保证未来所有模型能力、thread/turn 接口语义和桌面内部协议永远兼容。模型能力的独立验证、按单个增强功能降级、更完整的 schema 差异检查仍是后续工作；详见[兼容性研究](../2026-10-25-codex-update-resilience.md)。

## English

Only recognized direct stdio app-server commands enter the enhancement path. Startup-policy commands and unknown command shapes remain native. Both platforms revalidate changed runtimes in an isolated home with a complete handshake and manager-owned config readback. Failed checks fall back before consuming client input, keep saved preferences, and never replay user requests. Verified runtimes retain existing enhancement behavior. Native macOS acceptance remains outstanding; one historical premature-compaction reproduction also fails with the unchanged baseline on the tested Windows CLI.
