# 0.27.14

- 修复内建浏览器把登录验证 iframe 当作顶层跳转拦截的问题，允许必要的官方验证地址和可信页面的空白子框架。
- 第三方登录保留真实弹窗、同一隔离会话和 opener 回调，不再把新窗口强行改为当前页跳转或丢弃 POST 表单。
- macOS 支持网页 JavaScript 对话框，明确约束网页尺寸和焦点；两端增加返回、重新载入、复制链接及系统浏览器入口，并显示加载或跳转失败提示。
- 登录仍受身份提供方对嵌入浏览器的兼容性限制；系统浏览器可继续使用同一授权请求。

验证：原生 WKWebView 本地用例覆盖邮箱继续、验证 iframe 执行、真实空白弹窗及 opener 回传；共享导航用例同时校验 Swift 与 JavaScript 的允许/拒绝结果。已在 macOS 官方页面验证测试邮箱可进入密码页、Google 登录页及 Apple 系统验证弹窗可打开；补齐 Microsoft 验证子框架后，Microsoft 登录表单正常加载，未再触发拦截提示。Windows 仅完成逻辑回归，未进行实机登录。

Microsoft 的额外嵌入依赖依据 [官方登录页](https://login.live.com/) 当前返回的验证/品牌配置核对，仅允许在验证子框架内加载。
