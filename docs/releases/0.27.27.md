# Context Manager 0.27.27

## Browser-compatible macOS launch

The previous launch chain placed Context Manager's Node process between ChatGPT and the original Codex executable. A controlled desktop comparison reproduced `dynamic_app_tools_peer_rejected` with `untrusted-code-signing-identity` under that parent proxy, while direct native launch could enumerate the browser. This was a process-chain integration failure; the original Codex executable retained its OpenAI signature.

The macOS installer now registers a native launcher. It prepares the existing bridge, then execs the unmodified official runtime in the frontend's PID. The bridge runs as a child of Codex and transports its protocol through inherited pipes. The original signed Codex remains ChatGPT's direct child; no signature, browser permission, peer verifier or application bundle is patched. The existing Node bridge changes position, rather than adding another Codex server or monitoring process.

A bounded handshake completes before reading frontend input. Unknown utility commands and failed compatibility preparation exec the original command directly, without consuming or replaying its input. Runtime exit status still comes from the official frontend process, and bridge cleanup follows transport/client closure. Existing context-ceiling arguments, budget operations, task queues and native runtime selection use the same shared code.

## Platform validation

A desktop prototype of the new process layout successfully enumerated Chrome and the in-app browser while Context Manager stayed connected, with no peer-rejection entries in that session. The production launcher is independently tested for exact PID retention, binary/Unicode input preservation, original exit status, malformed-plan fallback and helper-failure fallback. Actual-runtime loopback integration exercises budget changes, history, permissions, forks, compaction and service restart through the production launcher.

macOS uses its native UI and launcher. Windows retains its existing launcher because the macOS peer-authorizer is platform-specific; the shared wrapper path and behavior are unchanged for Windows and validated in CI. Windows manual hardware acceptance is not covered by CI. Restart ChatGPT/Codex normally after installing to load the new launcher; diagnostic scripts are no longer needed for normal launches.
