# Context Manager 0.27.29

Add a one-shot handoff for an agent's unfinished task. `chat schedule current --prompt-file checkpoint.txt --request-id ID [--after-operation OP] [--revision N]` returns a receipt, context/headroom and readiness gates. The agent can then end its current turn; the existing task scheduler waits for exact completion and starts one same-chat turn after the budget is loaded, any explicit compaction is complete and fresh quota passes the existing reserves. It does not restart the desktop app, enable regular queues, dispatch their unrelated tasks or create another runtime/monitoring loop.

Waiting intent is bound to the source turn, input epoch, model, budget and history. New user messages, interview answers, interruption, archive/delete/fork actions, relevant state changes, disconnection, pauses, 15-minute expiry or service restart invalidate it. Outcome uncertainty is terminal and not replayed. Up to 50 receipts are retained, with deduplication during retention. `chat schedules` inspects and `chat schedule-cancel` cancels an unstarted handoff; running work uses Codex Stop/steering. Save-only/stale operations cannot masquerade as loaded context. Verified explicit compaction allows the next real task request without relying on its old pre-compaction counter; the native runtime still owns context capacity enforcement.

The skill now emphasizes agent-owned task progression and task-specific assessment of quality, latency, context value and remaining work. User feedback refines that judgment; unresolved consequential tradeoffs prompt an interview, and necessary user decisions must not be bypassed by scheduling a continuation. Comfortable headroom remains a reason to continue normal work.

Shared service/CLI/bridge behavior applies to macOS and Windows; neither platform adds a new status panel. The browser-compatible macOS process chain is unchanged. Older connected runtimes need a normal Codex restart before `capabilities.scheduleAfterTurn` is true. Windows native packaging/UI/installation/update validation is automated CI, not manual hardware acceptance.
