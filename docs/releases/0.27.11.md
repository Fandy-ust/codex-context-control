# 0.27.11 — Credits protection

- 新增套餐额度耗尽系统通知。默认 5 小时和每周额度都为 0 时提醒，也可选择任意一项为 0。通知提示后续请求可能使用 Credits，不将额度耗尽误报为已实际扣费。
- 可选“触发时停止全部当前任务（每轮一次）”，默认关闭。开启后暂停所有任务队列，并请求中断已接入会话中的当前轮次；同一账号同一轮耗尽只执行一次，额度恢复后重新启用。
- macOS 和 Windows 提供相同设置。更新后请重开 Codex 加载新的任务中断能力；未接入管理器的 CLI 会话不受控。管理器须保持后台运行并允许系统通知。

## Behavior and limits

Open Settings → Quota activation → Credits protection, choose the quota trigger, and save. Notifications default on and one-shot interruption defaults off. Protection uses only fresh, identified current-account readings from the Codex quota pool; stale readings, missing windows, and cloud-only account caches cannot initiate a stop.

The one-shot claim is persisted before interruption. Restarts, repeated polls, and switching away and back do not replay that episode. Fresh observed quota recovery rearms protection. Enabling interruption during an already exhausted episode performs its single stop if it has not yet been claimed. An uncertain or failed attempt is shown in settings and is not automatically retried.

Interruption targets the current turn IDs in connected runtimes and pauses every task queue. It does not close Codex or kill external services. New manual work started after that snapshot is not repeatedly interrupted. Older runtimes and failed requests are reported as partial rather than a confirmed stop; reopen Codex after updating.

Native quota polling can lag actual usage. This feature cannot guarantee that no Credits will be charged, and quota exhaustion alone does not prove that Credits were spent. System notification permissions and a running desktop manager are required for banners; interruption is performed by the background controller.
