# 0.26.0

Settings → Quota activation adds optional weekly reset detection and a one-time date/time schedule. It uses a separate ephemeral GPT-6 Luna turn, requests only “OK” and interrupts on the first response. It never interrupts a working chat.

Weekly detection observes expiration or a drop from used quota to a fully reset window, including resets that retain the old timestamp until first use. It verifies a fresh timestamp near the probe start plus seven days. Scheduled and manual activation verify five hours instead. The default tolerance is ten minutes, configurable from one to sixty. Each activation has at most three attempts; attempt counters are saved before sending, and uncertain sends are not replayed after a service restart.

Schedules use the computer's local time and run once. Keep the computer awake and the controller running. Schedules missed by more than fifteen minutes are marked missed. Already active windows do not require another message. Missing or stale quota readings defer execution. The feature uses the Codex quota pool and does not make a model request if its required window is missing.

Wake-up recommendations report a relative lead, not a clock time: five hours minus estimated time to consume a full window. They use up to ten cycles in the past twenty-one days for the current account and Codex pool, exclude gaps longer than twenty minutes and require at least three cycles with substantial observed use. A median and interquartile lead range limit the effect of unusual sessions. These are estimates; changes in models, workloads and idle time can change actual consumption.

The feature starts disabled. Both Windows and macOS use the same scheduler and recommendation code. The native Mac view requires validation on macOS.

Windows Setup uses LZMA2 compression and the existing stable installation/data directories. It upgrades the normal installation in place. The automatic update archive remains standard ZIP for compatibility. No Lab profile is used.
