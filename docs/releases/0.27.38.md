# 0.27.38 — Send the first message before historical accounting

A newly created empty user chat uses the budget already supplied in its creation request. Its first submission no longer waits for historical reasoning accounting or the model metadata needed by that accounting. The bridge records this eligibility only for an empty, non-forked creation and consumes it when a manual or automatic turn is submitted. Later messages still run accounting, including after interruptions or missing usage notifications. Resuming a chat does not restore eligibility.

Both macOS and Windows use the same bridge. Initial window/compaction configuration, input-size protection, and fork/resume history checks remain enforced.

Validation: focused regressions cover first submission without model metadata/history, second-turn accounting and successful submission, interrupted turns, missing notifications, inherited/resumed history, oversized input, and automatic tasks. The macOS installer is built locally. Windows packaging and native Windows execution require a Windows host.

Local acceptance: the full suite passed 573 of 589 tests, with 16 platform/opt-in skips and no failures; shared architecture checks passed. The 220 packaged payload files matched their manifest. The installed macOS app and controller report 0.27.38; the installed executable and bridge hashes match the installer payload. Existing Codex bridge processes retain their loaded code until a normal client restart.
