# 0.27.39 — Reject incomplete startup model catalogs

The active runtime was pinned to an extension catalog containing only the hidden `codex-auto-review` model, while the subsequently refreshed native cache contained the configured `gpt-6-astra` and other user-facing models. Startup previously accepted any nonempty cache, allowing a scoped cache to replace desktop model discovery for the entire process lifetime.

The shared macOS/Windows startup path now rejects caches with no visible (or legacy unspecified-visibility) entries, and caches missing the model explicitly selected in the root user configuration. In those cases it supplies no generated catalog or context overrides, leaving native discovery available. Once a usable cache is present, the next runtime launch can enable the configured context enhancements again. It does not reuse a previous account's catalog, alter the configured model/provider, or change model names/visibility. Existing first-turn accounting checks remain covered.

Validation: targeted tests cover hidden-only caches, missing configured models, native launch arguments on fallback, source preservation, and recovery with a full catalog. macOS artifacts and installation are checked locally; native Windows packaging and execution require a Windows host. Existing Codex processes require a normal restart to load the new catalog.
