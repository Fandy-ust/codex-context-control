# 0.27.0 — 多账号授权与主动切换（实验）

新增 **设置 → 账号切换**，与 0.26.7 的统计账号列表分开管理。统计中出现邮箱不代表已保存可切换的登录。

- 账号卡片右侧复用侧栏的 Credits、5 小时和每周额度组件，显示已缓存的实际重置时间；没有可靠对应观测时显示额度不可用。
- 侧栏账号标签稍加粗并增高，已保存登录的非当前账号旁增加快速切换按钮。点击后展示目标账号确认弹窗，取消不会发起切换；无法明确对应到登录账号时不显示快捷按钮。

- 通过官方 Codex app-server 的 ChatGPT OAuth 添加账号。默认打开系统浏览器，可选择实验性的应用内授权：Windows 使用独立临时 Electron 会话，macOS 使用非持久 WKWebView。用户自行完成账号选择、密码、MFA 和授权。
- 支持保存当前文件登录、账号简称、移除保存的登录，最多保存 20 个账号。移除登录不退出当前账号，也不删除统计。
- 本机账号保险库使用 AES-256-GCM 加密；保险库密钥存入 Windows DPAPI 或 macOS Keychain，不进入数值云同步。授权 URL、Token 不进入常规状态或日志；临时登录目录在进程退出后清理。
- 切换检查尊重全局监视暂停和单个队列暂停，不把已断开的历史任务状态当作运行中。存在真实会话或活动队列时，确认弹窗提供“强制停止并切换”：用户点击后暂停队列、取消额度探测并结束 Codex/CLI 进程，确认退出后才切换；不会关闭 IDE 本身。停止失败不会写入新登录。切换期间暂停队列派发，防止检查后启动新任务。
- 切换保存当前文件登录的最新凭据，在隔离进程中读取并验证目标账号，保存刷新后的凭据，然后再次检查进程与登录文件是否变化。启用顶层 `cli_auth_credentials_store = "file"`，保留其余配置和聊天历史；系统钥匙串原凭据保留。
- 普通配置写入失败时尝试恢复原文件。切换成功后尝试重新打开配置中的 Codex 桌面，无法自动打开时提示手动打开。运行中热切换、自动按额度轮换及跨设备凭据同步不属于本版本。

## 验证与试用边界

Windows 模拟界面验证包括账号添加、改名、确认切换、移除、输入草稿保持与敏感字段不进入页面。测试覆盖原生 RPC、取消和连接失败、账号身份不符、外部文件争写、加密保险库、进程检查及认证控制 API，以及暂停状态、强制停止确认、停止失败保留原登录和切换期间队列不派发。全量回归 438 项：395 通过、43 按平台或实机条件跳过、0 失败；架构检查通过。已完成 Windows 目录构建与 ZIP 打包，并通过真实内置运行时在未登录隔离目录中的 account/read 检查。

本次开发没有读取真实账号 Token、没有切换正在使用的真实账号，也没有执行真实浏览器授权或停止真实任务；真实会话停止、账号和工作区切换仍需实机试用验证。macOS UI 已同步实现，但本次 Windows 环境不能验证原生编译和运行。

该功能是 Codex 原生 OAuth 登录管理，不是另建 SIWC 动态客户端的推理客户端，也不是账号风控规避工具。内嵌浏览器可能被身份提供方限制，此时使用系统浏览器。操作系统或组织强制的认证策略、特殊 TOML 配置、突发断电及桌面版本差异仍可能影响切换，不能承诺零封号或所有桌面版本无感兼容。

官方接口参考：[App-server authentication](https://learn.chatgpt.com/docs/app-server)、[Credential storage](https://learn.chatgpt.com/docs/auth)。
