# 额度分析

Mac 和 Windows 共用同一统计核心、图表数据和栏目顺序。两端侧栏都提供「额度分析」入口，设置位于顶部版本号旁，底部保留 Credits 与额度周期指示。

## 预测首页

默认显示当前账户实际提供的额度周期。5 小时和 Weekly 分开计算，各自显示当前剩余、按近期速度用完还需多久、重置时预计剩余多少，以及「预计提前多久用完」或「预计仍有多少未使用」。没有 5 小时额度就不展示这一项。

下方只显示所选当前周期的剩余额度走势。横轴使用真实日期／时间，实线是实际读数，虚线从最近读数延伸到用完或重置，不计入重置后新增的额度。

预测只使用已识别的当前账户和同一额度池，不借用「账户未标识」的历史。速率以当前周期最近一段连续观测的净消耗除以实际经过时间计算，包括读数不变的时段。超过 30 分钟的断档、读数下降或 reset 变化会重新开始估计；重置时间 60 秒内的舍入偏差会先归一化。5 小时至少需要 15 分钟、Weekly 至少需要 1 小时的连续观测，并且至少消耗 1 个百分点。5 小时读数超过 15 分钟、Weekly 超过 30 分钟未更新时暂停预测。已到重置时间、记录不足、尚未识别账户或额度读数未变时，明确说明暂不能预测，不显示无限可用或虚假的零消耗。

结果表示持续保持近期速度的情景，不是保证。睡眠、暂停、切换模型，以及另一额度周期用完后的停用，都可能改变后续实际消耗。两个周期独立推算，不保证能同时维持相同速度。

## 高级分析

额度预测和高级分析显示在同一页：上方是当前账户预测，向下滚动即可使用模型筛选和历史图表，不再需要进入高级分析或返回预测。

「高级分析」保留历史曲线、Token／额度关系、效率、热力图和排行，可选择模型、来源、额度池及最近 4／8／12 周。选择模型后，本机 Token 和排行筛选该模型；额度关系与效率仅使用单模型区间，不将混合模型的账户变化按 Token 分摊。账户已用百分比、Weekly 消耗曲线及历史速度外推始终代表整体账户，界面会明确标识；当前账户的预测在首页单独计算。

各图直接展示“怎么看这张图”，解释坐标、颜色或柱高的含义，以及如何结合模型、任务质量和样本量作比较。说明不再以可展开的原始数据列表呈现；数值大小没有统一的好坏标准。

历史来源默认自动选择有可比较记录的来源，也可手动固定；来源身份始终标明，旧历史不会自动归为当前账户。Weekly 历史对比按 reset 时间向前推算 7 天对齐，各组不一定是连续完整的自然周。没有 5h 记录时隐藏对应图表。

## 数据来源与边界

- 通过只读的 `account/rateLimits/read` 取得额度；`account/read` 使用 `refreshToken:false`，只用于区分账户观测，不执行登录、退出或重置额度。接口字段以 [官方 App Server 文档](https://learn.chatgpt.com/docs/app-server) 为依据。
- 历史曲线回填自本机 rollout 中已有的额度快照。旧记录没有可靠账户身份，因此单独标为「本机历史（账户未标识）」，不会自动归到当前账户。
- Token 来自本机逐请求 `token_usage_record`。按响应 ID 去重，忽略 fork 复制的父请求；缓存输入已包含在输入 token 中，推理已包含在输出中，不再重复相加。历史被压缩、截断或回滚，不会退回已经发生的消耗。
- 没有 5h 记录时，效率图按 weekly 周期汇总，weekly 曲线和换算仍可使用；5h 指标及相关图表自动隐藏。
- 5h 和 weekly 按实际 `windowDurationMins` 识别，不假设 primary 一定是 5h。缺失周期不显示，不补成零。
- 同一来源、额度池的重置时间允许 60 秒内的倒计时舍入偏差，真实重置和读数下降仍会中断比较。散点与效率允许在同一周期内比较较长间隔的净变化，并明确标注断档估算；小时分布、预测和窗口归因仍只使用不超过 30 分钟的连续观测，不补造中间消耗。跨 5h 重置的差值不强行归给某个窗口。
- Token／百分点是本机相关观测，不是官方兑换率。额度可能包含其他设备的使用，本机 token 也不保证覆盖所有账户活动。低于 1 个百分点的变化先累积；缺少 token 时不生成换算；未知模型不会被归因到具体模型。
- 模型比较汇总可识别的单模型区间，少量样本只作参考；混合模型不分摊。拟合仍需至少三个不同输入的有效点。预测从最后一次观测外推：中线按有效观测时长计算平均速度，较慢／较快线使用小时聚合的经验速率，不是保证或统计置信区间。对话和项目排行榜只展示 token，不捏造逐聊天额度百分比。

## 缓存与维护

`quota-history.sqlite` 保存数字观测与扫描位置，`quota-history.key` 用于生成本机加盐账户指纹；不保存邮箱、登录 token、消息正文或工具参数。保留最近 366 天，两个数字记录表各最多 250,000 条。额度对比最多展示 12 周，费用日历可展示一年，较大的图形序列进行显示抽样，统计和拟合仍使用保留的全部有效样本。

扫描在独立 worker 中按预算分批执行，空闲 30 秒后释放 worker；首次导入显示进度，之后只读文件新增部分。未变化的文件不重读，大消息记录不会整体进入内存。没有本地副本的远端聊天不能计入本机 token。

Credits 基准由共用服务保存到 `quota-preferences.json`，两端按同一规则处理首次余额、余额增加与手动重置。旧 Windows 本地基准仅在余额匹配时迁入，明确重置过的基准不会被旧数据覆盖。更新保留这些文件，卸载也沿用保留用户数据的规则。

## 开发入口

- `src/core/quota-analytics.mjs`、`quota-statistics.mjs`：统一计算、样本选择和质量边界。
- `src/core/quota-chart-catalog.mjs`：共享图表目录与栏目。
- `src/analytics/ledger.mjs`：数字记录、去重、追加扫描和保留策略。
- `src/quota-analytics-service.mjs`：worker 生命周期及账户指纹。
- `macos/QuotaAnalytics.swift` 与 `desktop/renderer/quota-analytics.mjs`：原生与 Web 渲染。

开发预览使用明确的合成数据，不读取真实账户。回归覆盖跨周期、取整、断档、重复请求、fork、局部写入、文件替换、账户分组、HTTP 鉴权，以及两端渲染。

## Token 费用日历（0.21.4）

支持热力图/折线图切换和日、周、月、年范围。日按本地小时，周按最近七天，月按本月天数。年热力图按最近 365 天，年折线图按最近 12 个日历月；当月截至当前时刻。时区使用报告时区。缺少记录时断线或空格；有 Token 但无法计价时不计成零元，合计显示已计价部分并列出无法计价请求数。

费用沿用聊天详情 `estimateResponseWithWrites(..., 'standard')`，包含模型、长上下文价格档位、缓存读取/写入、输出，不重复增加推理 Token。缺少模型/缓存输入或无价格时保持未知。旧记录无写入字段时沿用原估算规则。价格使用现有共享价格表，不是服务商账单。数据仅为本机历史，模型筛选生效，账户来源/额度池/高级分析时间范围不改变费用日历。最多保留 366 天和 250,000 条记录；首次升级重扫可访问日志以补历史，导入进度未完成时金额不完整。

## 分析展示与日期筛选（0.21.5）

默认简洁模式显示实用图表，高级分析保留统计分类。共享报告提供 `simpleChartIds`、`interpretation`、`reliability`，两端使用相同规则。读图说明收进标题提示，技术数值默认折叠。可信程度为样本量和离散程度的描述性提示，不是统计置信概率，也不是官方兑换率。

费用接口支持 `costDate`（本地日历日期）、`costStart` / `costEnd`（UTC 毫秒时间戳，开始包含、结束不含、最多 366 天）。日期切换决定小时视图和快捷范围基准，自定义范围对请求先过滤再汇总，金额和图表口径一致。自定义范围不影响额度预测或额度历史统计。
