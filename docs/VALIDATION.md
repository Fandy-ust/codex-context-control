## 集成测试覆盖

- A 的窗口从 500K 调至 400K，读回可用窗口从 475K 改为 380K，B 保持 258.4K。
- 新的可用容量输入 700K 反算为底层 736,843，原运行时读回 700,000；压缩阈值按 90% 计算为 630,000，Hook stats 使用同一可用容量口径。
- 控制服务在生成期间更新后，原运行时继续完成请求，桥接自动重连；两种已验证内核版本均通过。
- 调整前后完整历史、模型、沙盒和审批策略保持一致。
- 基础指令、开发者指令和动态工具定义继续出现在原运行时请求中。
- 生成中提交的调整会等待该轮结束。
- 在调整事务期间提交新输入，仍能完成请求并读回目标窗口。
- 压缩阈值通过原内核真实触发压缩；最近请求统计由模拟服务提供。
- 本地 HTTP 接口拒绝未认证和来自浏览器 Origin 的请求。
- 开发者指令、请求正文不会进入控制服务状态文件。
- 旧版 SQLite 的完整首条提示词标题不导入，预览缓存迁移保留已有预算。

## 首次接入仍需要的用户动作

真实桌面已接入，并确认了底层 700K 预算对应 665K 的运行时读回。用户通过原来的 Codex 图标重开后，自动接入已确认。0.4.1 修复菜单栏应用包装与启动等待；`doctor` 分别报告控制连接、菜单对象创建、菜单窗口状态和位置。全新安装仍需正常重开一次以加载启动环境；已有接入可直接更新菜单栏应用，无需中断当前聊天。

Hook stats 的新增定义需要在 `/hooks` 人工审核。该信任状态不由安装程序写入。

模拟服务测试不代表真实长输入接受边界、真实压缩质量或任意未来运行时兼容性。自动启动测试不请求麦克风、录屏或辅助功能权限，真实麦克风权限归属仍需正常重开桌面后确认。本工具没有为验证而额外发送真实模型请求。

0.5.1 问题定位：用户反馈一次调整后先看见约 400K，再下一轮才是目标值。本机仅筛选窗口事件，确认实际报告过 425K，之后才是 363K；最新预算在第一轮前已保存。存储中存在两个新增修订号，但旧版没有逐次提交审计记录，不能据此认定用户手动提交了两次。代码中可复现的连续预算调度缺陷已修复；真实桌面仍需正常重开以载入新版桥接，不能把安装完成当作连接代码已热替换。

0.6.1 名称同步回归：使用独立 SQLite 索引验证 fork 的当前 name 覆盖旧桥接缓存、后续重命名能够刷新、归档/取消归档状态更新、预算不变，以及不导入 title 中的首条提示词。
