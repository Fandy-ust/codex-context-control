# 历史推理计数与预算应用

从 0.27.30 起，在安全的轮次边界应用窗口或压缩阈值之前，控制器先从本地保留历史中计算推理长度估算，再将窗口和阈值连同计数余量一次加载。恢复本地聊天也先做该估算。读取复用有界的数值缓存，支持普通和 `.zst` 记录；不启动额外 Codex server，不反复获取模型列表，不缓存推理内容。

用户设置的是真实目标：原生模式遵守模型上限，拓展开启后最多 920K。额外估算只用于原生端的计数窗口和压缩阈值，CLI 的 `loaded` / `headroom` 保持真实目标，`accounting` 单独报告额外估算及运行时数值。真实用量接近目标或预留量时仍会压缩。

这是一项边界时的估算调整，不能保证整轮运行中永远不会提前压缩。轮内用户追加输入会改变推理计数边界，新生成内容也可能增长；原生端仍负责自己的容量检查。历史无法可靠读取时，不能把推理估算当作零来声称新预算已完成。

旧的手动提前压缩补偿开关仍停用，旧内核补丁仍禁止使用。此实现只向官方运行时传递配置，保留 App → 官方 Codex → Node 连接子进程的启动链，不改官方二进制、签名检查或 Chrome 权限。更新后正常重开 Codex 一次以载入新桥接代码；预算保存与实际窗口确认仍有区别。
