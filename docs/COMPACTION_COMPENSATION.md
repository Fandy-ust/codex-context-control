# 提前压缩补偿（实验性）

在「设置 → 通用」开启 **提前压缩补偿**。默认关闭，与「拓展上下文」是独立开关；作用于开启自动应用、已设置预算的聊天，在下一轮提交或应用预算时生效。

**Codex 显示的上下文窗口可能更大，用于为重复计数预留空间；目标容量以 Context Manager 为准。** 聊天页会显示含补偿的运行时读回窗口。这里的目标容量是应用管理的预算，不是模型服务端容量的承诺。

## 如何工作

控制器读取当前本地有效历史，根据推理密文长度重现运行时的历史推理估算。已压缩掉的历史不再计入；分支只读取继承边界内的记录。内存缓存仅保留所需的条目类型、标识和密文长度，不持久保存推理密文或对话正文。

手动暂停也视为当前轮次结束，下一次继续前重新计算补偿。编辑消息后按不可变历史文件标识追溯继承记录，不把同一聊天的新文件误当作旧文件。升级后若提示重开 Codex，需要重开以加载新的连接程序。

提交新一轮前，在空闲聊天中更新原生窗口与压缩阈值，为预计额外计数预留空间。已保存的目标预算保持原值；应用仍按目标预算进行新输入预检，必要时先请求原生压缩。关闭开关后，自动应用中的聊天在下一轮恢复原窗口。

这是一项外层补偿，不替换官方二进制、不修改用量回包、不修改聊天历史，也不额外调用模型来估算。估算使用长度换算，并不代表真实的推理 token 数。

## 生效范围

- 普通本地聊天需要完整历史和最新用量；暂缺记录时显示「等待完整历史，暂未补偿」。
- 补偿后的窗口不得超过当前模式的模型目录上限。空间不足时使用原预算并显示提示，不把部分补偿标成完整生效。
- 接近 920K 等上限时可能无法补偿；它不能为模型增加真实容量。
- 无法确认的回退记录、缺少替换历史的压缩记录、临时或父代理管理的聊天不猜测补偿量。
- 补偿在轮次之间更新。供应方已正确计入推理、轮内新增指令边界、历史格式或原生估算规则变化时，行为可能有差异；它不保证消除全部提前压缩，也不把目标当成轮内每一步的硬边界。
- Computer Use 的完整兼容仍需实机验证；保持官方二进制不变不等于已完成该验证。

## 验证

自动测试覆盖历史替换、重复条目、回退拒绝、数据未落盘、容量上限、目标与运行时读回区分、开关认证及持久化。原版运行时的隔离测试比较开启与关闭后的提前压缩，并检查关闭后恢复原窗口。使用本地模拟响应，不消耗真实模型额度。

此前的「提前压缩修复」是替换运行时的旧补丁，仍然停用；本功能不启用那个补丁。
