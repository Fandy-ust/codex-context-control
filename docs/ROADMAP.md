# 后续路线

## 0.1：本地可用的核心

已实现：原生面板、逐聊天策略、窗口/阈值预检、轮次间重新加载、运行时窗口确认、Hook stats 输出、安装/更新/卸载，以及真实运行时的本地模拟集成测试。

当前开发环境已验证的运行时为 0.159.2 和 0.160.0；真正桌面接入情况由本机 doctor 显示，不用模拟测试冒充。

## 0.2：普通启动自动接入

已实现：安装一次后从原来的 Codex 图标启动，控制服务自动接入；设置面板按需打开。移除专用 Launcher，保留系统正常的应用启动链。登录登记可诊断、重复安装和卸载恢复。

## 后续体验改进

0.3 已实现：输入实际可用窗口、自动反算底层比例、按百分比联动压缩阈值、比例快捷预设与高级设置折叠。

0.4 已实现：随 Codex 自动出现的原生菜单栏入口、连接状态、设置窗口快捷入口，以及模型切换后的确认状态修复。

- 快捷键及更好的聊天选择/筛选。
- 逐聊天预设、项目默认预设，解释继承关系。
- 更完整的应用事务恢复和多窗口协调。
- 模型变化和客户端升级的兼容诊断。
- 用户选择恢复全局默认策略的明确操作。

## 后续研究

- 获得内核级别的实时上下文估算与压缩前缀基线，减少预检不确定性。
- 支持 body_after_prefix，前提是能可靠读到其基线与计数。
- 将可用比例调整作为单独实验，先区分客户端公式、模型目录与服务端限制。
- 与官方运行时合作，提供正式的逐聊天预算更新接口，减少重新加载。
- 官方开放消息工具栏扩展后，增加原位编辑控件。

这些是计划，不是当前已经具备的能力。
