# Codex Context Control

在 macOS 上，为每个 Codex 聊天单独设置上下文窗口和自动压缩阈值。

包含原生控制面板、Codex 连接桥接、Hook stats 状态输出，以及可重复执行的安装/卸载程序。使用原有 Codex 登录和运行时，不需要为本工具配置 API key。

**当前版本：0.5.2，本地预览版。已验证 Codex 0.159.2 和 0.160.0。** 窗口与压缩阈值均使用滑条，按 1K 调整；窗口变化时压缩阈值按比例联动。照常打开 Codex 后，菜单栏自动出现 **「上下文」**，点击即可打开设置。未验证的运行时仅透传，不执行预算调整。0.5.2 增加 fork 预算继承，并保留连续调整时下一轮前优先完成最新预算的修复。

## 软件形态

| 组成 | 使用方式 |
| --- | --- |
| **Codex Context Control.app** | 选择聊天、拖动窗口/压缩滑条、预检和提交 |
| **菜单栏「上下文」** | 随 Codex 接入自动出现，显示连接状态并提供设置入口 |
| 自动接入登记 | 让原来的 Codex 图标启动时自动载入连接桥接，无需另开启动器 |
| 本地控制服务 | 保存逐聊天预算，在轮次之间安排应用 |
| Stop hook | 将当前聊天的预算和应用状态显示在原生 Hook stats 中 |

窗口切换会暂时卸载并恢复**同一个聊天**，保留聊天 ID 和历史；不会重启整个 Codex 应用。正在生成的请求继续使用旧设置，调整在轮次之间执行。

## 快速部署

需要 macOS 14+、已安装的 Codex/ChatGPT 桌面应用、Node.js 22.13+，以及 Apple Command Line Tools（提供 Swift 编译器）。本项目没有第三方 npm 依赖。

```sh
gh repo clone Fandy-ust/codex-context-control
cd codex-context-control
npm run install:local
```

私有仓库需要先完成 GitHub 登录。也可使用 GitHub 提供的仓库下载方式取得源代码，再执行安装命令。

安装程序编译原生面板，在 `~/Applications` 创建一个设置应用，将服务代码放到 `~/Library/Application Support/CodexContextControl`，登记当前用户的自动接入，并向现有 `~/.codex/hooks.json` **追加一条自己的 Stop hook**。会先备份该文件，保留其他 hooks，不修改全局窗口配置，也不修改签名的 Codex 应用。升级时移除旧的专用 Launcher。

自动接入使用当前用户 GUI 登录会话的 `CODEX_CLI_PATH` 和一条登录登记任务。登记任务执行后退出；控制服务由 Codex 的运行时按需启动。该变量属于用户会话范围，其他读取它的工具也能看见；桥接只对识别到的 Codex 桌面调用启用，其他调用透传已配置的运行时。已有其他自定义值时停止登记，不覆盖；卸载时恢复本项目仍持有的设置。详见 [架构与接入](docs/ARCHITECTURE.md)。

### 首次接入

1. 完成本轮工作，然后正常退出原有 Codex/ChatGPT 桌面客户端。
2. 照常从 Dock、Spotlight 或应用文件夹打开原来的 Codex/ChatGPT。
3. 在原客户端打开一个已有聊天，进行正常的一轮交互，让工具读取实际窗口与最近请求用量。
4. 点击菜单栏 **「上下文」→「打开上下文设置…」**，选择聊天，预检并提交预算。关闭窗口后，菜单栏入口和预算控制继续工作。
5. 在正常的下一轮请求后，状态从“等待下一轮确认”变为“窗口已确认”。工具不会为确认设置而额外发送提示词。

需要在 Codex 的 `/hooks` 中审核并信任新增的 **Context Control** hook，才会显示相应 Hook stats 文字。未审核时，原生控制面板及预算控制仍能工作；安装程序不会生成或伪造信任记录。

首次退出/重新启动是为了让新进程取得自动接入配置。以后直接打开原来的 Codex 即可，调整预算无需重启整个客户端，也无需先打开控制面板。

## Fork 继承

正常 fork 已启用独立预算的对话时，创建请求直接带入父对话的窗口、压缩阈值、预留和保留下限。相同模型下，父对话为 363K，分支的第一轮也使用 363K。每个分支保存独立副本；后续修改父对话不会联动已有分支，再次 fork 会继承直接父分支的设置。没有独立预算或已停止自动应用的父对话保持原生默认行为。

## 调整例子

把窗口滑条调到 **700K**，选择 **90%**，压缩滑条即为 **630K**。把窗口改成 **400K**，压缩阈值自动变成 **360K**。两条滑条均按 **1K** 步进，旁边的 − / ＋ 可逐 K 微调；单独拖动压缩滑条会更新联动比例。保留 80%、85%、90% 快捷选择。

工具自动反算底层配置：在 95% 模型上，700K 对应底层 `736,843`，运行时取整后读回 **700,000**。当前模型最多可用多少，也按可用容量显示。滑条上限按模型目录和原生压缩规则计算，向下取整到 K。按比例联动时阈值也向下取整到 K，预览的 K 值就是提交值。下一轮预留和手动保留下限放在“高级设置”。

工具分别展示：

- 输入的目标可用窗口和按比例计算的压缩阈值；
- 运行时真正上报的可用窗口；
- 最近请求用量（当前占用的近似值）。

旧预算原样保留；面板按其实际可用容量显示，例如旧底层 700K 会显示为可用 665K。只有点击应用后才提交新的预算。旧值若不是整数 K，滑条草稿会向下取整到 K；顶部已保存预算仍显示原值。底层整数换算可在高级设置中查看。

“已保存”“已重新加载”“下一轮窗口已确认”是不同状态。接口返回成功，不代表窗口已改变。

## 功能边界

| 能力 | 0.5.2 |
| --- | --- |
| 逐聊天窗口、压缩阈值及预算持久保存 | 已实现 |
| fork 预算继承 | 创建时复制父对话预算；分支与父对话随后独立调整 |
| 双滑条、1K 微调、所见即所得与比例联动 | 已实现；自动反算底层预算 |
| 普通应用图标启动后自动接入 | 已实现；首次安装后正常重开一次 |
| 随 Codex 自动出现的菜单栏入口 | 已实现；可查看连接状态和打开设置，不自动弹出大窗口 |
| 生成中的调整排队 | 已实现 |
| 缩小前容量、预留和手动保留下限检查 | 已实现，基于可观测用量估算 |
| 同一聊天重新加载、恢复历史与执行设置 | 已验证上述两个运行时版本 |
| Hook stats 状态展示 | 已实现；需用户审核 hook |
| Hook stats 内嵌滑块/输入框 | 原生界面没有该扩展接口；使用独立原生面板 |
| 精确预测压缩后剩余 token 数 | 无法保证，必须压缩后重新测量 |
| 调整 95% 可用比例或突破 total 的 90% 规则 | 未实现，不改这些规则 |
| 修改服务端真实最大上下文 | 不支持 |
| 其他宿主、云端会话、父代理管理的子会话、临时会话 | 不支持 |

本工具不通过删除聊天记录缩减上下文，不把全局累计 token 当作上下文占用。最近请求用量也不等于内核的全部上下文估算，因此预检不能保证后续原生压缩绝不触发。

## 检查、更新、卸载

```sh
npm run doctor

# 取得代码更新后重新安装
git pull
npm run install:local

# 移除自动接入、设置应用和本工具的 hook；保留本地预算与备份
npm run uninstall:local
```

启动时会检查并更新本项目的旧控制服务。连接代码更新后，应在本轮工作结束后正常重开 Codex，以载入新版桥接。仅更新面板或重新打开设置窗口不能替换已运行的桥接。`doctor` 分别报告已安装版本、运行中的服务版本与 `loadedBridgeVersions`；桥接版本为 null 代表尚未支持版本上报的旧连接。卸载后仍按原来的方式启动 Codex；正在运行的连接在正常退出时结束。

## 验证

```sh
npm test

# 指定另一个本机运行时
CONTEXT_CONTROL_TEST_CODEX=/path/to/codex npm run test:integration

# 隔离测试完整安装、重复安装和卸载（会编译面板）
CONTEXT_CONTROL_TEST_INSTALL=1 node --test test/install.test.mjs
```

集成测试运行真实 Codex 内核，所有模型返回均来自本地模拟服务，不调用真实模型。验证历史、沙盒、模型、开发者指令、动态工具、阈值行为、排队与实际窗口确认；不验证真实服务端的接受边界或真实压缩质量。
